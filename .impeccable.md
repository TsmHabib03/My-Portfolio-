## Design Context

### Users
Recruiters, hiring managers, potential internship/freelance clients, professors, and fellow CS students scanning a first-year BSCS student's dev portfolio. They skim fast to judge real skill and credibility (actual GitHub activity, real certificates, real projects) rather than marketing copy.

### Brand Personality
Grounded, precise, quietly confident, GitHub-native / editor-calm. Not a flashy startup landing page, not a design agency showreel. Three words: diligent, technical, unpretentious.

### Aesthetic Direction
Static Tailwind-CDN + vanilla CSS/JS site (no React/build step — work within this stack, do not introduce a framework). **Light/default mode = original GitHub-Light** (crisp white, GitHub blue/green/amber) — a Tokyo Night Light conversion was tried and explicitly rejected ("sucks"), then fully reverted; do not re-attempt it unless asked again. **Dark mode = Tokyo Night ("Night")**, VS Code theme, kept. No purple/magenta anywhere in the site's own theme in either mode (explicit hard rule — Habib flagged purple as reading "vibe coded," this survived the light-mode revert); real third-party brand colors (PHP purple, Instagram gradient, Figma purple in the tech-icon pool) are the one exception, kept intentionally.

Light `:root`: bg `#ffffff`/`#f6f8fa`, border `#d0d7de`/`#f3f4f6`, text `#24292f`/`#57606a`/`#8b949e`, blue `#0969da`, green `#00b383`, amber `#f5a623`. Hero "& Web Developer" line uses `#e6950c` (amber, not the old purple `#4f46e5`).

Dark `[data-theme="dark"]`: bg `#1a1b26`/`#16161e`/`#1f2335`, border `#3b4261`/`#292e42`, text `#c0caf5`/`#a9b1d6`/`#565f89`, blue `#7aa2f7`, green `#9ece6a`, yellow `#e0af68`, orange `#ff9e64`, red `#f7768e`.

Display font Space Grotesk (already shipped site-wide, keep). Reference feel: GitHub profile / project README in light mode, authentic Tokyo Night VS Code editor in dark mode.

Banned (explicit, repeated user feedback across sessions): purple/blue AI gradients, gradient text, glassmorphism panels used decoratively, blurred glow blobs, pill-shaped status/availability badges with colored dots, three-equal-card generic feature rows, decorative-only effects, em-dashes.

### Design Principles
1. Refine the existing structure and section order; do not replace it with a new template.
2. No pill/dot "badge" components anywhere (nav, hero, cards, CTAs) — if status needs to show, use plain text, a number, or a real icon, never a `rounded-full` colored chip with a dot.
3. Real data over decoration: GitHub contribution graph should read as an authentic GitHub heatmap (correct grid, day/month labels, level-based green scale), not a stylized approximation.
4. One accent color family per section; reuse the existing CSS variable system (`--primary` / `--secondary` / `--accent`) rather than inventing new colors.
5. Motion is restrained and purposeful (hover feedback, entrance stagger, carousel transitions) — no gratuitous infinite loops or parallax.
